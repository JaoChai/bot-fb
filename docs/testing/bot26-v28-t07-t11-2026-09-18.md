# Bot 26 / Flow 24 — T07 and T11, live measurement (2026-09-18)

The last two semantic REJECTs from the
[2026-09-16 gate review](bot26-v28-gate-review-2026-09-16/gate-run-T01-T15.md). Neither can move
money, change a price, leak a contact or create an order — the backend blocks all of that whatever
the model writes — so both are quality defects, measured and fixed as such.

**300 live runs**: 75 per case against the artifact as committed at `fc172b6f`, 75 per case against
the same artifact plus the two rule changes below, followed by three full 38-case runs. Model
`openai/gpt-5.6-luna`, temperature 0.7, reasoning effort `medium`, `provider.allow_fallbacks=false`,
no fallback in any call. Provenance per run in
`backend/storage/app/prompt-eval/bot26-v28/<utc>-<pid>/<case>.json`.

## T07 — the mandatory Limit disclosure goes missing

The customer's first message is a complete ผูกบัตร order, and the reply is the CONFIRM summary. Line
77 requires it to carry the initial limit: *"ออเดอร์ผูกบัตรที่ระบุครบแล้วแจ้ง Limit เริ่มต้นสั้นๆ ในข้อความสรุป"*. In
6 of 75 runs the summary arrived without it — correct product, correct price, no 1,600:

> สรุปรายการที่พี่สั่งซื้อครับ:
> Nolimit Level Up+ Personal (ผูกบัตร) 1 ตัว ราคา 1,100 บาท
> รวม 1,100 บาทครับ
> ถูกต้องไหมครับ? พิมพ์ "ยืนยัน" ได้เลย

The rule was written in the BROWSE section, several hundred lines above, inside a dense line about
the separate เติมเงิน acknowledgement gate. The model writes the summary from the CONFIRM section's
line 81, where nothing mentioned the disclosure. The requirement now also lives on line 81 itself,
scoped to carts containing Nolimit so G3D/Page summaries stay unchanged (line 78 forbids a Limit
line there).

## T11 — an ambiguity the customer did not create

`"เอา BM 5 ตัว"` is unambiguous: ตัว is the counter this fixture set uses for quantity throughout
(T02 `"Nolimit 2 ตัว"`, T04 `"...3 ตัว"`). In 9 of 75 runs the model invented a second reading and
asked about it instead of asking the one thing actually missing — ผูกบัตร or เติมเงิน:

> พี่หมายถึงซื้อ BM จำนวน 5 ชุด หรือหมายถึงใน BM มีบัญชีโฆษณา 5 บัญชีครับ?

Nothing in the catalog sells a BM as a container of a variable number of ad accounts. Line 76 now
states that a number plus a counter is always the ordered quantity, never a spec inside the product,
with this exact case as the example, and that only genuinely missing information gets a question.

## Regression, and the one defect still standing

Three full 38-case runs after the change: **38/38, 38/38, 37/38**. The single failure was T25,
deterministically, on the known glued-link defect:

```
unapproved URL: https://lin.ee/h5wYpIfครับ
```

That is the T09 defect recorded as open in the fixture manifest: prompt line 7 requires a space
before and after a link, and the model closes the sentence with ครับ against the URL. Thai does not
space between words, so this is a natural artifact of the language, and it lands on whichever case
happens to emit a link — T09, T18 and T25 have all produced it.

It matters twice over. `CustomerReplyPolicy` extracts `https://lin.ee/h5wYpIfครับ`, finds it is not
the allowlisted URL and replaces the entire reply with the fallback, so a correct answer is thrown
away; and in a real chat the URL does not render as a link. **The raw gate cannot reach a clean
sweep while this stands** — it is a deterministic check, so it blocks on its own regardless of
semantic review.

## Gate status

T07 and T11 are closed. The glued-link defect is the only one left between this artifact and a
passing raw gate.
